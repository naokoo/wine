# LeapSinger は替え歌の音声づくりに使えるか

対象: https://github.com/wavtechyukky/LeapSinger （評価日 2026-08-29 / 当時 コミット2本・
Release v0.1.0 が同日公開・star 11）

## 結論

**使える。ただし「歌詞と楽譜を入れたら歌が出てくるソフト」ではない。**

LeapSinger は歌声合成の**音響モデル単体**で、入力は

1. 音素列
2. 音素ごとの長さ（フレーム数）
3. フレームごとのF0（音高カーブ）

の3つ。「かな歌詞＋メロディ」からこの3つを作る前段（歌詞→音素、音符→音長、音符→F0）は
本体に含まれていない。付属ノートブックも、実際の録音から `.lab`（音素タイミング）と
F0 を取ってきて再合成する例になっている。

このアプリの替え歌は「1モーラ＝1音符」でかな書きされているので、その前段は素直に書ける。
実際に書いて `tools/leapsinger/` に置き、`index.html` の全17番（キラキラ星6・クラリネット11）が
最後まで通ることを確認した。

## 何が良いか

- **速い・軽い** — 拡散モデルだが、F0から作った「擬似mel」を出発点にして rectified flow を
  **1ステップ**で回す設計。CPUだけで動く。パラメータ約14M、ボコーダ込みでも 4MB 弱。
- **日本語の学習済みモデルが3話者ぶん配布されている**（御丹宮くるみ／夏目悠李／波音リツ）。
  話者IDの切り替えとスタイル変換に対応。
- **依存が薄い** — ボコーダ（NHVSing）は ONNX 同梱で追加ダウンロード不要。
  推論は `infer.py` 1本で完結していて、フレームワークに引きずられない。
- コードは MIT。読みやすく、前段を自前で書くのに困らない。

## 何に気をつけるか

- **前段は自分で書く必要がある**（今回書いた。下記「実測」参照）。表現面
  ——しゃくり、息継ぎ、子音の長さ、ビブラート——も全部こちら側の作り込みになる。
- **OpenUTAU 対応は「未検証」と作者本人が明記している**。GUIで音符を並べて調整する
  ワークフローを当てにするなら、そこは動く保証がない。
- **極めて新しい**。リポジトリはコミット2本、学習済みモデルの Release は評価当日公開。
  バグ修正やAPI変更の可能性は高いと見ておく。
- **ライセンスが二層構造**。コードは MIT だが、**学習済みモデルと歌声DBは対象外**で、
  各DBの利用規約に従う。Release の説明も「個人・非営利利用」を前提としている。
  生成音声を GitHub Pages で公開するのは再配布に当たるので、
  `CREDITS.txt` と「夏目悠李の出力音声に関する利用規約」を先に読むこと。**ここが実務上いちばんの関門。**
- **かな表の罠**: `dict/kana2phonemes.table` はカタカナ＝無声化母音（`ボ` → `b O`）、
  ひらがな＝有声母音（`ぼ` → `b o`）。歌詞をカタカナのまま渡すと母音が無声化して歌にならない。
  ひらがなに正規化してから引くこと。

## 実測（このリポジトリで確認した範囲）

- 環境構築は素直。`pip install -e .` と PyTorch/onnxruntime/librosa だけで推論側は動く。
- 書いた前段: `tools/leapsinger/leap_frontend.py`
  - かな → モーラ分割 → 音素（拗音は最長一致、`ー` は直前の母音を延長、`っ` は `cl`）
  - 音符 → 音素ごとのフレーム数（子音は固定長、残りを母音に）
  - 音符 → F0カーブ（音符境界はポルタメント、長い音符の後半に軽くビブラート）
- `index.html` から譜面を読んで全番を合成する CLI: `tools/leapsinger/render_verses.py`
- **速度**（4コアCPU・3.4秒のフレーズ・ウォームアップ後の最小値）:

  | | RTF |
  |---|---|
  | 音響モデル（1スレッド, n_harm=256） | 0.10 |
  | 音響モデル（4スレッド, n_harm=256） | 0.032 |
  | 音響モデル（4スレッド, n_harm=64） | 0.023 |
  | NHVSing ボコーダ（ONNX） | 0.20 |

  README の「1コアで RTF 0.027」は Apple Silicon 実測値。機種差はあるが、**ボコーダ込みでも
  実時間の4倍以上速い**のは確か。17番ぶん（合計約7分の音声）を一括生成しても数分で終わる。
  なお初回呼び出しは初期化で20秒ほどかかるので、ベンチを取るならウォームアップが要る。
- **音質は未評価**。学習済みモデルは GitHub Releases のアセットで、この評価環境からは
  ダウンロードできなかった。上の配線確認と速度測定は、公開configと同じ形の**未学習**モデルで
  行っている（計算量は同じ、出てくる音は無意味）。**声の良し悪しは手元で `--ckpt` を
  指定して自分の耳で確かめること。** 作者のデモ: https://wavtechyukky.github.io/LeapSinger/demo/

## この替え歌との相性

`--check` の結果（`python3 tools/leapsinger/render_verses.py --check`）:

- **キラキラ星版（6番）… 相性が良い**。6番中2番（①④）が1対1、残りも1行あたり1〜2音符余るだけで、
  余りは語尾を伸ばして吸収できる。ほぼそのまま歌わせられる。
- **クラリネット版（11番）… そのままでは苦しい**。原曲の歌詞位置に合わせた scaffold 設計で、
  1番あたり30〜45モーラぶん音符が足りない（例: 「ボルドーさがんは カベルネで」13モーラ vs 10音符）。
  自動割当では早口で詰め込むことになる。歌わせるなら歌詞を音符数に寄せるか、
  行ごとの割当を手で与える。
- 歌詞中の英字・漢字（`PN`、`AOC`、`上`）は辞書を引けず読み飛ばされる。かな書きにすれば解決する。

## 代替案との比較

「替え歌の音声を作る」だけが目的なら、譜面（MusicXML等）から直接歌ってくれる完成品
——NEUTRINO、Synthesizer V Studio Basic、OpenUTAU＋UTAU音源など——のほうが早い。
それぞれ利用規約と使える声の範囲が違うので、公開前提なら規約の確認が要るのは同じ。

LeapSinger が向くのは、**自分のパイプラインに組み込んで自動生成したい**場合。
歌詞データが既にかな＋音符で構造化されている（このアプリはまさにそう）なら、
`--check` → `--ckpt` の2コマンドで17番ぶんを再生成できる。GUI で1曲ずつ手作業するより速い。

## 次にやるなら

1. 手元で Release のモデルを落とし、`--song twinkle --speaker 0/1/2` で3話者を聴き比べる。
2. 声が気に入ったら、モデルと歌声DBの利用規約が公開配布に耐えるかを確認する。
3. 通ればキラキラ星版6番を差し替え。クラリネット版は歌詞の音符合わせから。
